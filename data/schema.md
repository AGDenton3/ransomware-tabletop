# Scenario format

Scenarios are plain JSON in `data/scenarios/<id>.json`. The engine has no scenario-specific logic: everything a scenario does is described here. Run `node tools/validate.mjs` after every edit.

A complete small example is [`scenarios/_sample.json`](scenarios/_sample.json). Files starting with `_` are test fixtures: they are validated but not listed in the picker.

## Top level

```jsonc
{
  "id": "clinic",                    // must match the file name
  "title": "Brazos Valley Family Clinic",
  "orgType": "Healthcare",           // shown on the scenario card
  "difficulty": "Intermediate",      // free text: Intro | Intermediate | Advanced
  "estMinutes": 12,
  "startTime": "07:42",              // wall-clock time at Hour 0 (default 07:42)

  "orgProfile": {
    "name": "Brazos Valley Family Clinic (fictional)",
    "size": "40 staff, one location",
    "description": "What the organization does.",
    "criticalSystems": ["Electronic health records", "Scheduling"],
    "backups": "Nightly to a NAS on the same network; weekly cloud copy.",
    "insurance": "Cyber policy with a 24/7 breach hotline.",
    "regulatedData": ["Protected health information (HIPAA)"]
  },

  "ransomNote": {                    // the splash screen at the start
    "gang": "Fictional group name",  // NEVER a real ransomware group
    "demand": "$450,000 in Bitcoin",
    "deadlineHours": 72,
    "text": "The note's text."
  },

  "startingMeters": { "cost": 0, "downtime": 0, "dataLoss": 0, "trust": 72, "legal": 15 },
  "scoring": { "costBad": 1500000, "downtimeBad": 336 },  // optional: values that score 0

  "hiddenFacts": { ... },            // see below
  "initialFlags": { "someFlag": false },  // optional extra flags
  "start": "nodeId",
  "board": { ... },                  // situation board, see below
  "nodes": { "nodeId": { ... } },
  "injects": [ ... ],
  "benchmark": { ... }               // generated by tools/walk-all-paths.mjs --write
}
```

### Meters

| Key | Label | Range | Better when |
|---|---|---|---|
| `cost` | Cost ($) | 0 – 10,000,000 | lower |
| `downtime` | Downtime (hours) | 0 – 2,160 | lower |
| `dataLoss` | Data Loss (%) | 0 – 100 | lower |
| `trust` | Public Trust | 0 – 100 | higher |
| `legal` | Legal Exposure | 0 – 100 | lower |

Values are clamped to their range. `effects` anywhere are **deltas** (e.g. `{ "downtime": 6, "trust": -5 }`). Costs are illustrative, not real-world estimates.

### Hidden facts and flags

Flags are named values (usually booleans) in the game state. A flag that was never set reads as `false`.

`hiddenFacts` are the truth the player does not know at the start. Each becomes a flag with its `value`. The `preparation` block feeds the debrief's "Preparation would have changed this" section.

```jsonc
"hiddenFacts": {
  "nasEncrypted": {
    "value": true,
    "label": "The on-network NAS backup was encrypted too",
    "preparation": {
      "measure": "Keep an offline or immutable backup copy and test restores",
      "csf": "PR",
      "detail": "Backups reachable from the domain are encrypted along with everything else."
    }
  }
}
```

The player "discovers" a fact when a choice sets a separate flag (e.g. `checkedBackups: true`); the situation board and branches can then combine both.

### Conditions

Used by `requires`, conditional `next`, inject `if`, and board states. All keys must match:

```jsonc
{ "checkedBackups": true, "nasEncrypted": true }   // flag values
{ "$clockGte": 24 }                                // clock is at least Hour 24
{ "$clockLt": 6 }                                  // clock is before Hour 6
```

## Nodes

```jsonc
"scope": {
  "title": "How did they get in?",   // the heading (receives focus)
  "clockAdvance": 3,                 // hours added when the player arrives here
  "inbox": [                         // shown in order in the left column
    { "from": "Dr. Lena Ortiz, Practice Owner", "channel": "email", "subject": "Patients", "body": "..." }
  ],
  "narrative": "What the player sees and must decide about.",
  "effects": { "downtime": 12 },     // optional: applied on arrival
  "setFlags": { "reachedRecovery": true },  // optional: set on arrival
  "choices": [ ... ]                 // 1–4 choices
}
```

`channel` is one of `email`, `phone`, `text`, `news`, `portal` (the attacker's negotiation portal). Each gets its own card style.

### Choices

```jsonc
{
  "id": "isolate_now",               // unique within the node
  "label": "Pull the affected machines off the network now",
  "hint": "Stops the spread. Patients get rescheduled.",
  "csf": "RS",                       // GV | ID | PR | DE | RS | RC  (NIST CSF 2.0 Function)
  "legacyPhase": "Containment, Eradication & Recovery",
                                     // Preparation | Detection & Analysis |
                                     // Containment, Eradication & Recovery | Post-Incident Activity
  "keyDecision": true,               // high-value; skipping it is a "missed opportunity"
  "keyGroup": "call-insurer",        // optional: same choice offered on several nodes
  "effects": { "downtime": 8, "cost": 4000 },
  "setFlags": { "isolated": true },
  "requires": { "calledInsurer": true },  // optional: hidden unless met
  "clockAdvance": 1,                 // optional: extra hours this choice takes
  "next": "scope",                   // a node id, or conditional branches:
  // "next": [ { "if": { "nasEncrypted": false }, "next": "restore_fast" },
  //           { "else": "restore_slow" } ],          // must end with "else"
  "debrief": {
    "whyItMatters": "Shown on the debrief timeline.",
    "betterPractice": "What a well-run response does.",
    "realWorld": "Optional real-incident parallel, with a reference.",
    "referenceIds": ["cisa-stopransomware-guide"]    // ≥1, keys of data/references.json
  }
}
```

### Endings

```jsonc
"end_clean": {
  "title": "Doors open Monday",
  "clockAdvance": 48,
  "narrative": "What happened.",
  "ending": true,
  "outcome": "Contained and restored",   // the ending's name on the debrief
  "summary": "One-paragraph wrap-up."
}
```

## Injects

Events the player does not choose. After every move, each inject that has not fired yet fires once its `atHour` has passed **and** its `if` condition matches. Its message appears at the top of the next inbox.

```jsonc
{
  "id": "leak_post",
  "atHour": 24,
  "if": { "dataExfiltrated": true, "paid": false },
  "message": { "from": "Attacker leak site", "channel": "portal", "body": "..." },
  "effects": { "trust": -10, "legal": 10 },
  "setFlags": { "leakPosted": true }
}
```

## Situation board

What the player knows right now. Each item shows the text of the first matching state, or `default` (use `"Unknown"`; never blank). `tone` is `good`, `bad` or `warn`.

```jsonc
"board": {
  "items": [
    { "label": "Exfiltration",
      "states": [
        { "if": { "confirmedExfil": true }, "text": "Confirmed", "tone": "bad" },
        { "if": { "ruledOutExfil": true }, "text": "Ruled out", "tone": "good" }
      ],
      "default": "Unknown" }
  ],
  "notifications": [ { "flag": "notifiedInsurer", "label": "Insurer" } ]
}
```

## Rules the validator enforces

- Required fields above are present; `csf` and `legacyPhase` use the allowed values.
- Every `next` target exists; conditional `next` ends with `else`.
- No node is unreachable; the graph has no cycles; every reachable node can reach an ending.
- Every choice has `debrief.whyItMatters`, `betterPractice` and at least one `referenceId` that exists in `data/references.json`.
- Meter deltas use known meters and stay within sane limits (cost ±5M, downtime ±720 h, data loss ±60, trust and legal ±50).
- No real ransomware group is named outside debrief notes.
- `data/scenarios/index.json` entries point at real files.
